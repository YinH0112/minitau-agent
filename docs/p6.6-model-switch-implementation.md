# P6.6：模型配置如何随会话恢复

本阶段实现了同一 Provider 内的 `/model` 切换，以及模型配置的持久化、启动覆盖和分支重放。运行中的跨 Provider 切换仍按 [P6/P7 路线图](p6-p7-roadmap.md) 留在下一阶段。

## 改动与原因

| 位置 | 改动 | 原因 |
| --- | --- | --- |
| `minitau_agent/session/entries.py`、`memory.py` | 增加 `ModelChangeEntry`，在所选历史路径上取最后一条配置 | 配置和消息遵守同一条 `parent_id` 历史链；旧分支的模型不会污染新分支 |
| `minitau_agent/harness.py` | 增加 `append_model_change()`，由 Harness 负责追加并推进链尾 | Harness 本来就拥有链尾；由别的模块直接写 JSONL 会让下一条消息接到旧节点 |
| `minitau_coding/session.py` | 新建会话写初始配置；`set_model()` 写成功后再换运行配置；恢复、`/resume`、`/branch` 按活动路径还原配置 | 落盘失败时内存仍用旧模型；显示状态、下一轮请求和磁盘历史保持一致 |
| `minitau_coding/session_manager.py` | 快照携带活动分支的 `model_change` | CLI 和 CodingSession 可以从同一份已校验快照决定有效配置 |
| `minitau_coding/cli.py` | 先加载快照，再用存储的 Provider 名创建实例；保留显式参数标记 | 未传 `--provider` 时能恢复原 Provider；`--model`、`--context-window` 不会被旧日志覆盖 |
| `minitau_coding/commands.py` | `/model <name>` 等待异步写入完成 | 命令报告成功时，变更已经落盘 |

## 一次切换的数据流

假设初始模型为 `alpha`，用户输入 `/model beta`：

1. `commands._model()` 调用并等待 `CodingSession.set_model("beta")`。
2. `set_model()` 检查 Harness 空闲和模型名，再调用 `append_model_change()`。
3. Harness 追加一条 `model_change`，其 `parent_id` 指向当前链尾。只有追加成功才更新链尾。
4. CodingSession 随后把 `beta` 写进自身配置和 Harness 配置。下一次 `prompt()` 从 Harness 读取 `beta` 发给 Provider；已有消息列表不变。

会话文件的关键形状是：

```text
session_info → model_change(alpha) → 用户消息 → 助手消息 → model_change(beta) → 下一条用户消息
```

`ModelChangeEntry` 只保存 `provider_name`、`model`、`context_window_tokens`。API key 仍由 Provider 工厂从环境读取，绝不写入会话文件。

## 恢复时选哪个模型

有效值的优先级是：**显式启动参数 > 活动分支最后一条配置 > Provider 工厂默认值**。例如，会话里保存了 `beta`，普通 `--resume` 会继续使用 `beta`；若本次启动加 `--model gamma`，本次进程用 `gamma`，但仅启动覆盖本身不会改写旧的 `model_change`。窗口大小同理。

`/branch` 先持久化叶节点选择，然后重放根节点到该节点的路径。如果路径上只有初始 `alpha`，即使别的分支后来写了 `beta`，当前分支仍恢复为 `alpha`。`/resume` 读取的快照也走同一套路径重放。旧 JSONL 文件没有模型条目时，沿用启动配置。

`/model` 保留当前窗口值：项目暂时没有可靠的“模型名 → 上下文窗口”元数据，不能仅凭模型字符串猜新窗口。可以在启动时用 `--context-window` 显式指定。切换后 `/status` 会用当前消息重新估算占用，并显示当前窗口。

本地只校验模型名非空且不含空白；不会为了验证模型是否存在而额外发送付费请求。因此 `/model` 成功表示配置已保存，真正的模型可用性由下一次请求确认。

## 验证

`tests/test_model_change_replay.py` 和 `tests/test_model_persistence.py` 覆盖条目序列化、无密钥字段、重启恢复、启动覆盖、分支模型回退、落盘失败回滚、会话切换以及 CLI 的 Provider 选择。旧测试也已按“新会话多一条初始模型记录”更新链尾断言。
